# Stepper Stand v2 — два мотора, Холлы, SSI и автотест

**Статус: экспериментальная реализация для стендовой приёмки.** Программные проверки и сборка не являются испытаниями вашего железа. Первый запуск — только после проверки питания, распиновки и физической аварийной цепи. На показанном владельцем переходнике установлен конденсатор 35 В: подавать на него 48 В нельзя.

Новый проект находится в `bench_v2/`. Старые `src/`, `data/` и корневой `platformio.ini` не заменены: это сохраняет возможность отката. На одной ESP32 одновременно работает только одна прошивка. Для v2 загружаются и прошивка, и её LittleFS. Старый веб-API с новым несовместим. Старые EEPROM-настройки намеренно не переносятся автоматически из-за противоречивых единиц и отсутствия версии формата.

## Что реализовано

Два независимых TMC5160 в **SPI Motion Controller mode**: отдельные настройки, включение, позиция, движение, исходная точка, автотест и ошибки. Обе оси могут двигаться, но синхронная интерполяция и общая траектория не реализованы. ESP32 не генерирует STEP-импульсы: разгон, торможение и позиционирование выполняют драйверы.

В интерфейсе задаются градусы **выходного вала**, скорость в °/с, ускорение и замедление в °/с². Команда движения сама включает исправный и настроенный драйвер; предварительно нажимать HOLD не нужно. Отдельное удержание осталось. Автотест выполняет заданное число циклов `левая → правая → левая`, с паузами и программными границами; есть заготовки ±45° и ±90°.

Поиск исходной точки использует выбранный датчик Холла либо StallGuard2. Поиск двух упоров — отдельный ограниченный наладочный проход: найти минимум, отойти, найти максимум, проверить рабочие ограничения, определить середину и перейти в неё. Постоянно ударять механизм об упоры при каждом цикле не предлагается.

На каждую ось доступны MIN/CENTER/MAX. При дополнительном соединении MIN/MAX с REFL/REFR TMC5160 они останавливают генератор движения аппаратно. Через один MCP23017 также видны все шесть состояний. Центральный Холл сам по себе обрабатывается программно.

Есть два настраиваемых SSI-канала: Gray/Binary, полный позиционный отсчёт, вывод сырого кадра, калибровка нуля, восстановление позиции по энкодеру и отключение при устойчивом рассогласовании. **Это не сервопривод с автоматической коррекцией.** Поддержка именно экземпляра Hengstler 0541211 требует подтверждения полного matchcode, питания и формата кадра.

Бистабильный соленоид оставлен на прежних GPIO: одиночные импульсы A/B, ограниченный тест, остывание и проверка Холлов. При первом неподтверждённом переключении тест прекращается. Старые расширенные сценарии повторных попыток и статистика задержек в v2 не перенесены; старая реализация сохранена отдельно.

## Сборка и прошивка

Команды из корня репозитория:

```sh
python -m pip install platformio==6.1.18
pio run -d bench_v2
pio run -d bench_v2 -t buildfs
# Отключить силовое питание и подключить ESP32 по USB:
pio run -d bench_v2 -t upload
pio run -d bench_v2 -t uploadfs
```

Зафиксированы `espressif32@6.10.0`, Arduino ESP32 2.0.17 и `ArduinoJson@6.21.5`. Плата — ESP32 DOIT DevKit V1 / WROOM. GPIO16/17 нельзя занимать так же на WROVER с PSRAM. Номера COM-портов при необходимости задаются через `--upload-port COMx`.

После прошивки отключить USB и вернуться к проверенной схеме питания от лабораторного источника. Не соединять одновременно USB 5 В и выход понижайки без развязки/подтверждённой схемы питания конкретной DevKit.

Точка доступа: **Krya-Stand-v2**, первоначальный пароль **bench-setup-2026**, адрес `http://192.168.4.1`. Пароль находится в `src/main.cpp`: сменить перед использованием вне изолированного стенда. Это локальный сервис без TLS и полноценной аутентификации; не выставлять его в интернет.

## Первый запуск

1. Прочитать [схему и список деталей](../docs/bench_v2/WIRING_AND_BOM_RU.md). Отключить моторную нагрузку или механически обезопасить её. Проверить NC-цепь GPIO39: при нажатии аварийной кнопки силовое питание снимается независимо от ESP32, а вход становится HIGH.
2. Открыть панель, нажать «Взять управление». Оба драйвера по умолчанию `present=0`, `commissioned=0` и выключены. Параметры NEMA не подставляются как гарантированно безопасные.
3. В параметрах мотора 1 задать паспортные полные шаги, фактическое передаточное число и ограниченный пробный ток. `gear = обороты мотора / оборот выходного вала`. Для подтверждённого Mellow Pro V1.5 `rsense=0.033`. Значения 300/200 мА — стартовые заглушки, а не аттестация любого двигателя. `hold` — доля рабочего тока, а не ограничение тока лабораторного БП.
4. После фактической проверки отметить установленный драйвер и проверку проводки. Применить настройки. До применения обе оси и соленоид должны быть выключены. Требуется `SPI OK`; `SAVED_BUT_DRIVER_NOT_READY` означает, что настройки сохранены, но драйвер не готов.
5. Подтвердить готовность. Проверить сдвиги ±1° без нагрузки. Без установленного нуля разрешены только относительные перемещения до 2° на малой скорости. Сверить направление и масштаб по реальному валу. Аналогично проверить вторую ось, не включая сразу оба механизма.
6. Установить ноль вручную либо настроить датчик/энкодер. Проверить одиночные небольшие перемещения, затем один цикл и только затем длительный тест.

`Стоп` отменяет последовательность и тормозит, оставляя удержание. Во время поиска исходной точки Stop снимает ток и аннулирует исходную точку. `Аварийно` всегда снимает ток и блокирует продолжение. Освобождение вала может быть опасным при гравитационной нагрузке: требуется независимое удержание/тормоз.

Вкладка-владелец отправляет heartbeat каждые 400 мс. После 1500 мс без него начнётся остановка; это **не время полного торможения**. Скрытие/закрытие вкладки также запрашивает Stop. После восстановления связи автоматического продолжения нет. Физическая аварийная цепь обязательна: Wi-Fi, программный watchdog и EN не являются сертифицированной системой безопасности.

## Холлы и StallGuard

`hallMask`: MIN=1, CENTER=2, MAX=4; сумма выбранных датчиков. Например 5 — два крайних, 7 — все три. `hardLimits=1` включать **только после подключения и проверки** MIN/MAX к REFL/REFR. Метод `homeMethod=1` выбирает Холлы; `homeHall=0` — MIN, `homeHall=1` — CENTER. `homeCoordinate` задаёт координату обнаруженной точки. Отрицательное направление — направление поиска нуля.

Для StallGuard: `homeMethod=2`; `sgt` от −64 до +63, причём 0 — полноценное значение. Нужны подходящие ток и скорость для конкретного двигателя, напряжения, редуктора и механической нагрузки. Очень медленный ход не гарантирует надёжного определения упора. Настраивать сначала на разгруженном механизме в ограниченном диапазоне, с физической кнопкой остановки; `sgTuned` — подтверждение наладки оператором, не автокалибровка.

Работает SpreadCycle и внутренний `SW_MODE.sg_stop`. DIAG-провод для этого алгоритма не требуется. Защита вооружается только после выхода на `sgMinSpeed` и выдержки; отсутствие выхода на скорость, исчерпание `travel` или `homeTimeout` приводят к ошибке. Нет «безопасного на всех моторах» значения SGT. При старте уже в механическом упоре алгоритм не может надёжно определить исходную геометрию: начать со свободного положения.

После поиска двух упоров программа вычисляет середину. Настроенные `low/high` должны лежать внутри измеренного диапазона с запасом `backoff`; иначе движение прекращается с `LIMITS_OUTSIDE_MEASURED_RANGE`. Для первого измерения задайте заведомо узкий рабочий диапазон, например ±10°, **если механика его допускает**. Это не означает, что все устройства безопасно вращаются на ±10°.

## SSI: что необходимо уточнить

Название AC36/0541211 не заменяет полный код с шильдика. Семейство имеет разные разрешения ST/MT, питание и дополнительные биты. До подтверждения `frameConfirmed=0`: сырые данные видны, но позиция не признаётся достоверной. `frameBits` — число информационных тактов без дополнительного проверочного нулевого такта; `stBits/mtBits` — разрешения; `shift` — младшие биты после позиции. Сначала декодируется всё Gray-слово, затем выделяется ST.

В текущей версии используется энкодер **на выходном валу**, угол относительно сохранённого нуля, диапазон ограничен ±170°. Многовитковые данные декодируются, но непрерывная многовитковая координата и восстановление угла выхода по энкодеру на входе редуктора не реализованы. Для такой установки нужен отдельный режим с использованием MT и известным редуктором.

В интерфейсе: проверить направление/масштаб по нескольким известным углам; «Калибровать ноль энкодера здесь»; затем при последующих включениях «Взять позицию с энкодера». Потеря кадра или ошибка больше допуска дольше 250 мс приводит к отключению. CRC и интерпретация необязательного alarm-бита AC36 пока не реализованы. Проверка idle/trailing bit не заменяет контроль целостности данных; SSI не является единственным аварийным датчиком.

## Проверки и API

```sh
bash bench_v2/tests/run.sh
python -m pip install playwright==1.58.0
python -m playwright install chromium
python bench_v2/tests/ui_smoke.py
```

Нативные тесты используют ASan/UBSan и модели GPIO/SPI, браузерные — имитацию API. Подробности и аппаратная приёмка: [аудит](../docs/bench_v2/AUDIT_AND_ACCEPTANCE_RU.md).

`GET /api/status` возвращает снимок осей, конфигурацию, ошибки, сырой SSI, ревизию и последние результаты. `POST /api/command` принимает JSON. После `claim` нужны heartbeat и тот же `client`; ось 0/1. Движение возвращает HTTP202 с `accepted_id`, а **результат исполнения** читается из `results` статуса. Не считать 202 завершением движения.

Команды: `claim`, `heartbeat`, `ack`, `config`, `move`, `jog`, `hold`, `release`, `zero`, `home`, `scan`, `test`, `encoder_ref`, `encoder_zero`, `sol_enable`, `sol_release`, `sol_pulse`, `sol_test`, `stop`, `estop`. Stop/EStop обрабатываются вне обычной очереди и отменяют уже поставленные старые команды. Для конфигурации передавать текущую `revision`; флаги конфигурации — числа 0/1, `relative` команды движения — JSON boolean.
