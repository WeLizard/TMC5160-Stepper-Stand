# Обновление веб-панели стенда — 25.09.2026

Это доработка интерфейса `bench_v2`, а не привязка стенда к одному двигателю. Прошивка управления, GPIO, форматы API и NVS в этом проходе не изменены. Параметры каждой оси задаёт пользователь. Существующие ограничения движения и процедура аппаратной приёмки остаются в силе.

## Что изменилось

Две карточки показывают положение, цель, скорость, циклы и состояние MIN/CENTER/MAX. Для управления есть вкладки «Ручное», «Автотест», «Ноль и упоры». Рабочий ток, микрошаги, передаточное число, скорость и границы доступны в основной форме; параметры Холлов, StallGuard и SSI свёрнуты в «Дополнительно». Методы поиска выбираются из списка, датчики Холла — отдельными галочками вместо числовой маски.

Кнопки углов только подставляют число, движение начинается отдельной командой. Для малого сдвига можно выбрать 0,1°, 1° или 2°. «Стоп всё» и «Аварийно · снять ток» остаются в закреплённой шапке, в том числе без права управления. При отсутствии связи интерфейс показывает устаревшие данные и не утверждает, что механизм уже остановился.

## Сменные двигатели и профили

Восстановлены шаблоны NEMA 8/14/17/23. Их значения — редактируемые заготовки, а не определение допустимого тока по габариту. Загрузка шаблона или собственного профиля **не отправляет команду на ESP32 и не включает мотор**. После загрузки требуется проверить параметры и отдельно применить их. Подтверждение подключения, настройка StallGuard и калибровка нуля после смены профиля не переносятся автоматически.

Профиль содержит только полные шаги, микрошаги, рабочий ток, ток поиска и долю удержания. Передаточное число, границы, разгон, торможение, направление, распиновка и датчики остаются настройками оси. `gear = обороты двигателя / оборот выходного вала`; дробные значения, например `0.333`, допустимы без округления формы до сотых.

До 32 пользовательских профилей сохраняются **в локальном хранилище текущего браузера**. Они переживают перезагрузку страницы, но не переносятся на другой телефон автоматически. Есть экспорт и импорт JSON. Файл проверяется до записи; недопустимый файл не заменяет библиотеку. Импорт не применяет параметры двигателя. Имена выводятся как текст, не как HTML. Применённые параметры двух осей по-прежнему сохраняет сама ESP32 в NVS.

## Работа с правками

Неприменённые правки и введённые углы сохраняются отдельно для двух осей **до перезагрузки страницы**. Переключение на второй мотор и опрос статуса не стирают форму первого. При неприменённых настройках обычный пуск этой оси блокируется, чтобы не запускать её с другими фактически сохранёнными параметрами. «Снять ток» и общие остановки остаются доступны.

Если настройки той же оси изменились на контроллере, интерфейс сообщает о конфликте и требует перечитать данные. Изменение другой оси обновляет номер ревизии без потери текущих правок. Ответ на сохранение относится к оси, для которой была отправлена команда, даже когда пользователь уже переключил панель. Правки, внесённые после отправки, не выдаются за сохранённые.

После скрытия вкладки отправляется Stop и прекращаются heartbeat. Возврат или восстановление связи не возобновляет управление автоматически: нужно снова нажать «Взять управление». Это не замена аппаратной аварийной цепи.

## Как обновить

На уже установленной версии `bench_v2` с соответствующим API достаточно загрузить её обновлённую LittleFS из корня репозитория:

```sh
pio run -d bench_v2 -t uploadfs
```

Загрузку выполняйте при выключенной силовой части. После обновления перезагрузите страницу без кеша. Старый корневой проект `src/` + `data/` этим действием не обновляется: новая панель предназначена только для `bench_v2`.

## Проверки

`bench_v2/tests/ui_smoke.py` проверяет в Chromium обе оси, независимые черновики, дробную передачу, четыре шаблона, сохранение/экспорт/импорт/удаление профилей, некорректные данные и HTML в имени, отказ хранилища, конфликты ревизий, отложенные ответы, одиночные движения, автотест, соленоид, потерю связи и доступность остановок. Проверяется отсутствие горизонтальной прокрутки на ширинах 1440, 390 и 320 пикселей.

По умолчанию запросы HTTP перехватываются внутри теста, а localStorage и экспорт файлов используются настоящие браузерные. Для среды без разрешённых навигаций предусмотрен `UI_IN_MEMORY=1`: дополнительно имитируются транспорт и хранилище. GitHub Actions использует обычный режим. Ни один вариант не подключается к физической ESP32 и не подтверждает аппаратную безопасность стенда.
